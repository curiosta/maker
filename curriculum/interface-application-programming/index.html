What the official assignment asks for

Group assignment

  • Compare as many tool options as possible.

Individual assignment

  • Write an application that interfaces a user with an input and/or output device that you made.

How it is assessed

Paraphrased

From the Fab Academy 2026 assessment page on fabacademy.org, retrieved 29 Oct 2026. Your local and global instructors decide what passes.

Learning outcomes

  • Implement a user interface and explore protocols to talk to a microcontroller board you designed and made.

Clarified in the official FAQ

  • The application must work with a board you made.
  • A command-line interface can count if it behaves like a user interface.

All modules also follow the general essentials (original files in your archive, compressed media, acknowledgements, AI prompts documented) and the commercial board policy. Summary of both.

Documentation checklist

The official "have you answered these questions?" list for this module, paraphrased. Tick each one off in your documentation.

  • Linked to the group assignment page.
  • Documented your process.
  • Explained the interface you made and how.
  • Explained how your application talks to your board.
  • Explained problems and how you fixed them.
  • Included original source code (a screenshot only if there is no other way).
  • Included a hero shot of the application running and talking to your board.

Bare-minimum vs exceptional

Author's interpretation

Author's interpretation, not official Fab Academy grading. Use it to aim your work and check your documentation, and confirm what counts with your instructor.

Bare-minimum

  • An application on a computer or phone that reads from or controls your own board.
  • The communication (for example serial, Wi-Fi or Bluetooth) explained, with the message format.
  • Source code and a photo or video of it working.

Exceptional

  • Several tools compared in the group work and your choice justified.
  • Two-way communication: data shown live, and the interface sending commands back.
  • Errors handled: what the interface does when the board is unplugged or sends bad data.
  • The interface is the one your final project will use.

Common pitfalls

The author's notes, partly drawn from the official FAQ. Not official grading.

  • An interface that talks to a commercial board only.
  • Hard-coding a serial port name that only works on your computer.
  • No explanation of the protocol between app and board.
  • Screenshots of code instead of files.
